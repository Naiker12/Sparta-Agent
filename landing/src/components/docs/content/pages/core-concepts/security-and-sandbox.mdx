## Autenticación del motor

Las rutas protegidas requieren credenciales. Electron obtiene una sesión intercambiando un secreto local con el backend. El secreto permanece en el proceso principal; el renderer recibe tokens de sesión.

El acceso web utiliza contraseña. La renovación consume el token de refresh y entrega uno nuevo. Un token ausente, inválido o expirado no debe conceder una identidad válida.

## Permisos de herramientas

Las aprobaciones se vinculan a llamadas y sesiones. Revisa el comando y su destino cuando la aplicación solicite permiso. Las herramientas que acceden a servicios externos pueden operar con las capacidades de la cuenta conectada.

## Archivos y procesos

El proyecto incluye validadores de rutas y separación entre renderer, Electron y Python. La ejecución de un comando local no equivale a una máquina virtual ni a un aislamiento total del sistema operativo.

<Callout title="Límite importante">Una herramienta de terminal puede modificar archivos accesibles al proceso. Utiliza carpetas delimitadas y revisa los argumentos antes de autorizar operaciones sensibles.</Callout>

## Credenciales y datos

El backend utiliza almacenamiento cifrado para credenciales de proveedores. Existen rutas heredadas de persistencia en revisión; no atribuyas la misma garantía a todos los archivos locales.

Si usas modelos cloud, los mensajes y archivos incluidos en la petición pueden salir del equipo. Revisa también las políticas del proveedor.

## Acceso remoto

No confundas CORS con autenticación. Antes de habilitar LAN o túneles, verifica credenciales, alcance de red y sesiones. Consulta [Acceso remoto](/docs/features/remote-access).
