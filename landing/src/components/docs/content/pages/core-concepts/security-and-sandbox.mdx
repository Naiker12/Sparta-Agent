# Seguridad y Sandbox

La seguridad de Sparta Agent está fundamentada en el principio de **cero confianza no autorizada (Zero-Trust Local Engine)**. A diferencia de los asistentes que transmiten tu espacio de trabajo a servidores remotos, Sparta Agent implementa múltiples capas de contención.

## Principios de Seguridad Fundamentales

### 1. Invariantes del Sistema de Archivos
- **Rutas Relativas al Workspace**: Toda operación de lectura o modificación debe circunscribirse al directorio del workspace activo seleccionado por el usuario.
- **Prohibición de Sobreescrituras Ciegas**: El agente debe inspeccionar el contenido existente antes de aplicar cualquier modificación incremental.
- **Preservación de Integridad**: Si una edición genera errores sintácticos detectados por el parser de AST, la operación puede revertirse inmediatamente.

### 2. Sandbox de Ejecución de Comandos
- Los comandos de terminal se ejecutan en subprocesos aislados con variables de entorno restringidas.
- **Paginación Desactivada**: Se fuerza `PAGER=cat` para evitar bloqueos interactivos no gestionados.
- **Gestión de Procesos en Segundo Plano**: Cada tarea asíncrona cuenta con identificadores únicos, temporizadores de cancelación y aislamiento de streams `stdout`/`stderr`.

### 3. Cero Telemetría de Código Fuente
<Callout type="info">
  Sparta Agent no recopila fragmentos de tu código, historiales de conversación ni nombres de variables. La única conexión externa es la que el usuario configure explícitamente hacia su proveedor de IA o servidores MCP.
</Callout>

## Políticas de Auditoría en Tiempo Real

Cada acción ejecutada por el agente genera un registro inmutable en formato JSON Lines (`transcript.jsonl`) almacenado en el directorio de la aplicación, permitiendo:
1. Inspeccionar cada llamada a herramientas y sus argumentos exactos.
2. Comprobar la respuesta devuelta por el sistema.
3. Auditar la cronología completa de cambios para trazabilidad de equipo.
