## Dos canales con responsabilidades distintas

**IPC:** operaciones del escritorio, como ventana, archivos y acceso al proceso principal mediante el preload.

**HTTP:** peticiones al backend Python para funcionalidades como chat, proveedores y conexiones actuales.

## Autenticación del renderer

El renderer solicita una sesión mediante `backend:authenticate`. El proceso principal comprueba la ventana y el origen, intercambia su secreto con el backend y devuelve únicamente tokens de sesión.

## Contratos heredados

Hay canales de compatibilidad cuyo nombre o estado no demuestra una implementación funcional. Antes de añadir un consumidor, comprueba que el canal tenga un handler real y que devuelva errores explícitos cuando no esté disponible.

## Al cambiar un canal

Actualiza el handler, la API del preload y sus consumidores juntos. Añade una prueba de la operación y de su rechazo cuando el origen o los argumentos no son válidos.
