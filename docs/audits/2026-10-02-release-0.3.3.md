## Publicación y actualizaciones

Los builds locales y de CI usan `--publish never`. El flujo de release reúne Windows, Linux, macOS Intel y macOS Apple silicon antes de publicar. Los instaladores de macOS incluyen la arquitectura en su nombre; sus metadatos se combinan y se verifican las sumas de los archivos anunciados. La landing se construye antes de publicar y se despliega después de que estén disponibles los instaladores.

El runner Intel se actualizó a `macos-15-intel`, conforme a [la documentación de runners de GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) y [la retirada de macOS 13](https://github.com/actions/runner-images/issues/13046).

Los builds de macOS y Linux requieren los runners de GitHub; no se presentan como comprobaciones locales. El resultado remoto y los archivos publicados se verifican después de subir el tag.

La primera ejecución remota se detuvo en `npm ci`: npm 10.9.9 exigía registrar el peer opcional `@pierre/theme@1.1.0` utilizado por `@pierre/trees`. El lockfile generado con npm 11 no contenía esa entrada. Se añadió su versión e integridad sin cambiar las versiones declaradas del producto. La validación de instalación limpia con npm 10.9.9 se aprobó para raíz, frontend y landing. Se repitió el flujo remoto con este ajuste; no se publicaron assets durante la ejecución fallida.

La reinstalación real de las dependencias raíz también se completó con npm 10.9.9; después pasaron Vitest, TypeScript y Vite. El build remoto de Linux llegó a aprobarse. Se detuvo esa ejecución para adaptar el recolector de assets a las carpetas de versión conservadas por [upload-artifact](https://github.com/actions/upload-artifact#upload-using-multiple-paths-and-exclusions). Una prueba de integración reproduce los cuatro directorios anidados, combina los metadatos y comprueba que alterar un binario impide publicarlo.

## Limitaciones pendientes

`npm audit --omit=dev` informó 12 avisos en el árbol de dependencias: nueve altos, dos moderados y uno bajo, sin críticos. No se ejecutó `npm audit fix --force`, que proponía cambios incompatibles. El informe incluye herramientas clasificadas como dependencias y no demuestra por sí solo la exposición del instalador; hace falta una revisión por dependencia y ruta de uso.

El build informa de chunks grandes e importaciones dinámicas que también se usan de forma estática. Son oportunidades de optimización, no errores de compilación. Las llamadas a proveedores reales y una instalación limpia completa quedan fuera de estas pruebas.
